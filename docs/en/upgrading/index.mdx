# Upgrading

This documentation provides information about upgrading the Alauda Build of OpenTelemetry v2, including:

- Upgrading the Operator and updating the OpenTelemetry Collector configuration
- Upgrading the auto-instrumentation agents injected into application pods

## Upgrade Path

The table below contains the complete upgrade path. When upgrading, you need to upgrade the versions in sequence. Skipping a version is not supported.

| No. | Alauda Build of OpenTelemetry v2 | OpenTelemetry Operator | OpenTelemetry Collector |
| --- | -------------------------------- | ---------------------- | ----------------------- |
| 1   | v2.0.z                           | 0.147.0                | 0.147.0                 |
| 2   | v2.1.z                           | 0.157.0                | 0.158.0                 |

Upgrading the Operator restarts every managed Collector, and a Collector that does not pin `spec.image` picks up the Collector version listed in the same row. For the Alauda Container Platform versions supported by each release, see the [Compatibility and support matrix](../about/release-notes/compatibility-support-matrix.mdx).

:::info
In the version numbers above, the `.z` indicates the latest available patch version for that minor release.
When performing an upgrade, you should always use the most recent patch version to ensure you benefit from the latest security updates and bug fixes.
The latest patch versions for each release can be found in the [Release Notes](../about/release-notes/).
:::
